# Build and replace libraries — v1.0.2

These are developer instructions for the separately supplied corresponding source. Researchers only need the Windows Setup download.

1. Extract `NilePhytoDock-v1.0.2-Corresponding-Source.zip` into a dedicated writable folder on Windows x64. It includes the essential seed/resources and the exact shipped Java/P2Rank/Smina runtime inputs. The seed is a library catalog, not a research working database.
2. Install Python 3.12.14 x64 for the developer environment. Create a virtual environment with `python -m venv .venv`, then run `.venv\Scripts\python -m pip install -r requirements.txt`.
3. From the source root, run `.venv\Scripts\python -m PyInstaller --noconfirm --distpath dist_v1_install --workpath build\pyinstaller_rebuild build\NilePhytoDock-release.spec`. The spec produces the installed-folder payload used by Setup. A portable one-file candidate can optionally be built by setting NILE_BUILD_ONEFILE=1, but the validated release uses the single Setup download. It resolves and filters the same scientific/native dependencies rather than replacing application algorithms.
4. Run `.venv\Scripts\python -m tools.build_v1_setup`. The existing Windows .NET Framework compiler builds the source-provided setup and maintenance executable. The output is `release/NilePhytoDock-v1.0.2-Setup.exe`. Create the `release` folder first if needed. No commercial installer compiler is required.
5. License/source manifests and the guide are placed in the installed Documentation folder. The compiled Python application is in `NilePhytoDock.exe` and its runtime libraries in `_internal`. The installer contains an ordinary ZIP payload in its `NilePhytoDock.Payload` .NET resource; it is not encrypted.

The original release's Qt/scientific extension DLLs are from the exact versions pinned in requirements.txt. To modify an LGPL library, build an interface-compatible DLL/extension from the supplied matching source and its upstream build instructions, close the application, and replace the installed library in `_internal` (or the corresponding native-engine subdirectory). No signature lock prevents replacement. Application source may also be edited and repackaged with that library. Reverse engineering for debugging modified LGPL components is permitted.

`NilePhytoDock-v1.0.0-Dependency-Sources.zip` from the unchanged [v1.0.0 dependency-source release](https://github.com/ahmedGSoliman99/NilePhytoDock-Source/releases/tag/v1.0.0) contains the locally mirrored source archives/JARs indexed in THIRD_PARTY_SOURCES.json. For Qt WebEngine, extract its wrapper source and place the separately linked complete Chromium source tree at `src/3rdparty`. The full pinned upstream tree and downloadable archive are public without authentication. Follow Qt's build instructions for the intended Windows/MSVC toolchain. Java source is the matching Temurin 17.0.19+10 source; OpenBabel source and the Smina 2020.12.10 source plus dated conda recipe and patch are included. P2Rank's original default model and necessary JARs are provided; its own MIT source is publicly available at the pinned 2.5.1 tag. The custom BioJava, FasterForest and FasterMolecularSurface sources are provided separately.

Build scripts intentionally leave the original developer/user databases and older release folders intact. Reproducible application source signatures were verified against the v1.0.2 frozen archive. Native third-party binaries were tested and identified by their original hashes/version; byte-identical native compilation is not asserted. The native Qt wheel does not disclose its compiler's Git SHA; supplied upstream release sources and the exact reported Chromium version are distinguished in the license audit.

Historical archives preserve the original 0.6.0/0.6.1 app and build inputs without relabeling their validation. Their older Windows packages may be needed to reproduce their original layout exactly. Original versioned dependency sources, upstream repositories and notices remain available; these older packages are not the current supported download.

To prepare the current corresponding-source archive, run `.venv\Scripts\python -m tools.package_update_sources` after freezing and staging the installer. Keep the previous source archives and their published checksums. The shipped seed is unchanged; no user studies are release inputs.

The verified build uses a Python ssl module with a public CA distrust hook. See build/runtime/README.md: preserve this supplied module and the public policy file for the same TLS behavior. The spec includes the required PEM at the frozen runtime root. A missing policy caused the original packaged PDB-download failure; certificate verification was never disabled to fix it. Python's full PSF license and the exact runtime-specific source are retained.
